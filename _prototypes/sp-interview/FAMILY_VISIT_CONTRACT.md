# Family Visit local runtime contract

Implementation of `docs/superpowers/plans/2026-09-05-family-visit-simulator.md`. Local draft only. Separate server on `127.0.0.1:4320`, page `/_prototypes/sp-interview/family-visit.html`. Existing Dana server/pack stay intact.

## Shared browser/server protocol

- `GET /api/family/health`: `{configured,caseId,caseHash,title,participants:[{id,name,pronouns,voice,description}],limits:{turns:10},localOnly:true,operations,usage}`. `operations` reports process-scoped used/reserved actor and speech operations, active calls, and limits. `usage` reports allowlisted provider token totals and reporting coverage, or null when unavailable; `costUsd` remains null. No private facts, dialogue, credentials, provider IDs, or billing inference.
- `POST /api/family/session {}`: JSON room view. The learner opens the meeting; no automatic paid opening.
- Room view: `{sessionId,caseId,caseHash,channel,status,turnCount,maxTurns,targetRoleId,events,retryEligibleTurnIds,sourceTurnId?}`. Events have `{id,kind,roleId?,text?,channel,audience,turnId?,groupId?,segmentId?,status?}`. View is for the learner; actor projections remain server-only.
- `POST /api/family/turn {sessionId,turnId,text,targetRoleId,channel}`. `turnId` is an integer starting at 1 in each session. Targets: `morgan`, `maya`, `both`. Channels: `public`, `morgan-private`, `maya-private`. Reject stale/wrong channel, arbitrary keys, duplicate mismatches, or cross-role targeting in private. Identical completed request replay returns same segments, never new generation; concurrent duplicate may reject clearly.
- Turn/continue response is NDJSON: `{type:'segment',groupId,turnId,segment:{id,roleId,name,text,audioUrl}}`, then `{type:'complete',groupId,turnId,roleId,remainingRoles,room}`. On failure: `{type:'error',code,message}`; no raw provider errors. At most two ordered segments per actor, substantive first sentence then remainder, each validated. For ordinary public replies the first sentence may begin playing while the actor finishes; audio remains subject to final actor validation. If a public actor has private memory, no text, audio URL, or speech operation is released until the full reply passes both ordinary validation and the limited private-phrase guard. A blocked reply cancels the group with `private_reply_blocked`, discards queued roles, and releases only unused reservations.
- `POST /api/family/receipt {sessionId,groupId,completedSegmentIds,status}` with `status`=`played` or `interrupted`. IDs must be an ordered prefix of issued audio-complete segments. JSON `{room,canContinue}`. Completed means the native player ended, not merely received bytes. Server verifies audio finished before accepting, but cannot certify human listening.
- `POST /api/family/continue {sessionId,groupId}`: same NDJSON, next preselected role only, after complete receipt for first actor. The second actor sees only completed heard public segments. No automatic third response.
- `POST /api/family/cancel {sessionId,groupId?,completedSegmentIds?}`: stop pending actor/audio and all queued roles, preserve validated completed segments, settle budget, return room. IDs are a cumulative ordered prefix. Unlike strict `/receipt`, cancellation succeeds when a native-ended segment lacks final actor or audio validation: only the validated prefix is retained, and the uncertain remainder is omitted. Malformed, skipped, duplicate, or unknown IDs are rejected. Cancellation is safe to repeat; a late repeat cannot promote an already closed group's unheard segments.
- `POST /api/family/channel {sessionId,channel}`: only when no group pending; append immutable transition, return room. Authored fictional case explicitly permits brief separate check-ins for both participants; that permission is not inferred by a model. Private dialogue never becomes public automatically when rejoining. Retry child cannot change channels.
- `POST /api/family/finish {sessionId}`: stop pending work, mark finished, return room with eligible original learner-turn IDs.
- `POST /api/family/retry {sessionId,turnId}`: original must be finished; one idempotent child, before that learner turn, all participants and permission state preserved, target fixed to the original target, one alternative turn only. Returns child room. Original never mutated except child identity. No later event enters the child.
- `DELETE /api/family/session/:id`: deletes original/children/audio, returns `{ok:true}`.
- `GET /api/family/audio/:token`: same-origin streaming MP3. No files/credentials beyond explicit static allowlist.

## Behavior and scope

One role speaks at a time. A `both` turn atomically reserves two actor operations and four maximum speech segments before generating either. Reserve one/two for a single target. Release unspent reservation only; used/uncertain work remains counted. Shared per-process ceilings: 60 actor, 60 speech operations, two concurrent operations, eight sessions, 30-minute TTL. Ten learner turns in original; one in alternative. Provider is the existing pinned OpenAI adapter. Morgan maps to its existing Marin speech profile; Maya gets a separate Cedar profile. No numeric rapport, readiness, clinical diagnosis, or automatic agreement state.

The browser uses the existing turn-capture controller with a gated `externalDelivery` option: family respond callback owns ordered audio and receipts; on `{deliveryManaged:true}` it resumes input without adding a fake single-patient reply. Optional `{pauseAfterDelivery:true}` enters paused state without transient microphone rearming for completed-caption reading. Original behavior stays unchanged without that option. Source of family history is server events, never this microphone controller's internal transcript. Pause/interrupt/End abort the response and queue, wait for server cancellation before enabling more work. Private transitions stop recognition and audio before changing channels. No automatic microphone on refresh; explicit Start/Resume only. Page hide pauses; unload requests deletion; TTL handles lost connections.

Actor context includes public completed history and that actor's own completed private history, filtered by event audience. Private memories have explicit channel labels; all learner entries have server-derived addressee labels. Neither another actor's private history nor unasked private fact inventory enters a public actor request. Own memory is not disclosure permission. No sharing operation exists in this version. The secondary output check compares normalized four-token private phrases against authored public facts and completed public actor speech; learner claims do not authorize sharing. This lexical check cannot establish semantic non-disclosure for all possible replies.

Provider usage remains in memory for the lifetime of the adapter, with separate actor/speech `started`, `inFlight`, `completed`, `failed`, `cancelled`, `usageReported`, `usageMissing`, token totals and per-field reporting counts; recorded-speech hits are separate. Started attempts are not a claim about billable operations. Actual usage returned on failure is retained; missing usage is left unknown. Binary speech responses currently often lack token data. Process limits and usage observability are separate contracts; neither is a durable billing ledger.

Every rendered speaker segment is labeled speaking/completed/interrupted as applicable; exact full generated text is not represented as heard after interruption. Bookmarks refer to server turn IDs and retain original channel/target. Family reflection is optional and stored only in page memory. First pilot includes self-reflection and case-authored teaching prompts, no generated mind-reading or numerical evaluation.

## Ownership

The September 6 station modules (`sp-encounter-profiles.js`, `sp-encounter-rhythm.js`, `sp-encounter-ui.js`) use this protocol without new endpoints. Portrayal augments role-specific actor prompts under the existing facts/channel rules. Floor requests use completed public events and never generate a response automatically. Headphone recognition transfers one running listener through interruption or normal playback completion; exact acknowledgments create no learner event. Review context selection and attending dictation do not mutate server history or issue patient requests. Only completed server segments enter the exact-quote reflection; private contexts remain explicitly separate.
