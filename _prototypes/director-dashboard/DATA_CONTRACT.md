# Director dashboard — aggregate-only input contract (v1) and published aggregate (v1)

**Status:** prototype contract, not yet satisfied by any real producer. The committed feed
`metrics/aggregate/synthetic_feed.json` is SYNTHETIC (`"_synthetic": true`), generated by
`metrics/aggregate/synthetic_feed_generator.mjs`. Designed for data minimisation; **compliance
review pending** — nothing here is claimed to satisfy FERPA or any other regime.

**One engine.** `metrics/aggregate/cohort_aggregate.js` (`globalThis.CohortAggregate`) is the only
implementation of validation, aggregation and suppression. The dashboard loads it as a classic
script; the metrics site's read-only function `metrics/netlify/functions/cohort.mjs`
(`GET /api/cohort`, D-F8-2) imports it. Both call `publish(feed)`, which returns grouped,
suppressed totals only (below). Tested once: `tests/director-dashboard.test.mjs`.

The engine accepts one JSON feed. `validateFeed()` enforces every input rule below and
`publish()` **refuses** (throws; the page renders nothing, the function answers 503) if one
fails. Field sets are closed: an unknown field anywhere (for example `student`, `name`, `email`,
`learnerId`, `studyCode`) is a rejection, not a warning.

## Top level

| Field | Type | Required | Meaning |
| --- | --- | --- | --- |
| `_synthetic` | boolean | yes | `true` for mock data. The page's MOCK banner stays on regardless. |
| `_label` | string | no | Human description of the feed. |
| `contractVersion` | `1` | yes | This document. |
| `generatedOn` | `YYYY-MM-DD` | no | Day the export was produced (day, never time). |
| `suppressionThreshold` | integer ≥ 5 | no | Small-cell threshold. Default 5. May be raised; values below 5 are rejected (policy floor). |
| `rotationBlocks` | array | yes | The rotation calendar (below). |
| `counters` | array | yes | The metrics site's records (below). |
| `prepost` | array | no | Per-block pre/post feasibility aggregates (below). |

## `rotationBlocks[]` — the calendar, maintained by the director

`{ "id": "MS3-B1", "site": "ms3", "start": "2026-09-07", "weeks": 6 }`

- `id` short label (≤ 32 characters, not `all`); `site` `ms3` or `res`; `start` the block's first
  day; `weeks` 1–16.
- Blocks on one site may not overlap — ISO week → rotation week is ambiguous otherwise (the L8
  design's stated limit). The calendar is never derived from learner data.
- **D-F8-3 (decided 2026-10-27): the calendar of record is the already-committed
  `13_Faculty_Resources/_automation/maintenance/rotation_blocks.json`** (opaque `rot-YYYY-hx-…`
  ids, `startsOn`/`endsOn`, status; no names, rosters or counts; schema
  `rotation_blocks.schema.json` beside it). It holds the six MS3 Sanford blocks 2026-08-17 →
  2027-06-20 (from the UNECOM MS3 cohort confirmation, committed 2026-09-01). `blocksFromRotationConfig(cfg, site)`
  converts it to the shape above using the dates only; a second calendar file is deliberately
  not created. Residents' block dates are **not** in the repository (waiting on the
  coordinator), and the calendar carries no `site` field, so adding residents is a decision
  (a `site` field is a schema change, i.e. a governance PR).

## `counters[]` — exactly the metrics site's shape

`{ "site": "ms3", "week": "2026-W37", "key": "page:review.html", "n": 12 }`

- Exactly these four fields. `week` is an ISO week (the finest time grain stored anywhere);
  `key` an allowlisted `page:` or `tool:` key; `n` a non-negative integer count of **visits**.
- Keys the panels read: `page:*.md` (reading views), `page:*.html` (tool opens),
  `page:question-bank-practice.html`, `page:review.html`, and the nine draft outcome keys from
  PR #1076 (`tool:qbank:answered-5|10|20`, `tool:qbank:first10-lt50|50to79|80up`,
  `tool:daily-review:graded-1|10|25`). Records outside every rotation block are ignored.
- **Proposed, not emitted by anything:** `tool:qbank:cat:<category>:first10-lt50|50to79|80up`
  for the weak-topics panel. #1076 deliberately sends no category. Adding this family is a new
  allowlist and therefore a decision (it widens what a learner's browser sends, even if only by
  a category label); until then the panel shows "No category counters in this feed" on real data.
- Raw records may carry n < 5 — the metrics store holds them. Suppression happens in
  `publish()`, which is both the source (the function returns only its output) and the
  renderer's input (the page renders only its output).

## `prepost[]` — pooled feasibility only

`{ "block": "MS3-B1", "eligible": 14, "consented": 11, "paired": 9, "facultyHours": 1.5, "privacyIncidents": 0 }`

Produced by the honest broker from the pre/post scaffold (PR #1077), never by a learner site.
Integers except `facultyHours`; `consented ≤ eligible`, `paired ≤ consented`. The dashboard
pools these across all blocks on a site before computing any rate.

## Published aggregate (`publish(feed)`, `aggregateVersion: 1`)

Top level: `aggregateVersion`, `contractVersion`, `_synthetic`, `suppressionThreshold`,
`generatedOn` (if the feed had one), `sites`. Per site: `blocks` (`id`, `start`, `weeks`),
`protection` (`exact`, or `fail-closed` if exact protection could not be computed — then every
cell is hidden), `groups` (each block id, plus `all` = pooled over the site's blocks), and
`feasibility` (pooled pre/post rates; no counts).

A **cell** is `{ "shown": true, "n": 37 }` or `{ "shown": false }` — a suppressed cell carries
no value, so nothing downstream can display or forward it. Per group:

| Field | Cells |
| --- | --- |
| `reach[]` | per rotation week: `reads` (`page:*.md` views), `tools` (other `page:*.html` opens — the question bank and Daily Review are counted in the funnel, not here) |
| `funnel.qbank` / `funnel.review` | `opens`, and **disjoint** `tiers[]` that add up to the opens: qbank `lt5`, `5to9`, `10to19`, `20up`; review `none`, `1to9`, `10to24`, `25up`. Each with `share` of opens. `{ "withheld": true }` if the counters are inconsistent (a tier would be negative). |
| `bands[]` | per rotation week: the three first-10 accuracy bands and their `total` |
| `topics[]` | per category (proposed keys): `total`, `low` (<50%), `rest`, `lowShare` |
| `activeWeeks`, `blockWeeks`, `finalWeekReadShare` | derived only from shown cells |

## Suppression rules (pinned by `tests/director-dashboard.test.mjs`)

1. **Primary:** every cell below the threshold — zero included — is hidden. The page renders
   every hidden cell as `—`; a primary and a complementary suppression are deliberately
   indistinguishable (showing `<5` for one and `—*` for the other let a reader bound the hidden
   value).
2. **Identities.** The engine lists every identity a reader can use: each total and its parts
   (funnel opens = its tiers; band total = its bands; topic total = low + rest), each pooled
   cell and its blocks (`all` = Σ blocks, per cell), and PR #1076's answered-10 ↔ first-10 band
   identity (Σ weekly band totals = `10to19` + `20up`). For every identity, to a fixpoint:
   - it may not have exactly one hidden member (unless the value a reader would derive is 0);
   - if its hidden members are all on one side, the sum a reader derives for them (total minus
     the shown parts) may not be 1..t−1 — this is the nested-threshold and "all but k" rule;
   - when either fails, the smallest shown member is hidden too (complementary suppression).
3. **Combinations:** after the rules settle, an exact (integer Gauss–Jordan) audit over all the
   identities finds any hidden cell a reader could recover by combining them; each one found
   forces another complementary suppression. If the arithmetic cannot be done exactly the site
   fails closed.
4. **Nested thresholds — ENFORCED (D-F8-6, decided 2026-10-27; was a documented gap in v1).**
   Cumulative keys (answered ≥5 ⊇ ≥10 ⊇ ≥20; graded ≥1 ⊇ ≥10 ⊇ ≥25) are never published;
   they are converted to disjoint tiers covered by rule 2, so no difference between published
   tiers — or between a block and the pooled view, or across panels — yields 1..t−1.
   **Proof obligations in the tests:** an independent auditor rebuilds every published cell
   from synthetic *visit atoms* (not from the engine's identities) and checks, for the fixture
   and 12 adversarial random feeds, that (a) no two nested shown cells differ by 1..t−1 and
   (b) no natural category (any block × rotation-week range × tier range × band / key /
   category choice) holding 1..t−1 visits lies in the linear span of the shown cells. A
   vacuity control shows the same auditor finds leaks under primary-only suppression.
5. **Shares** of published counts are shown only when both counts are shown (they add nothing).
   Feasibility rates (counts never published) keep the v1 rule: suppressed if the numerator or
   denominator is below the threshold; only a lower bound (`≥81%`) when fewer than the
   threshold fall outside the numerator.

**Limits, stated.** A derived value of exactly 0 is allowed (it discloses absence, not a
person). Non-negativity still lets a reader bound a hidden cell by its identity's residual (a
hidden cell can be at most that residual, which is ≥ t or 0). Arbitrary unions of cells drawn
from different identities are not enumerated by the engine; the tests' category audit covers
the natural ones. Identities the producer might add later (e.g. a category ↔ overall-band
identity for the proposed topic keys) must be declared in `buildSite()` before they ship.

## What a producer must never send

Names, emails, student or study IDs, tokens, IP addresses, user agents, session ids, timestamps
finer than the ISO week, item ids, answers, scores, free text. The closed field sets above make
each of these a validation failure.

## The read-only function (D-F8-2)

`metrics/netlify/functions/cohort.mjs`, routed `/api/cohort` in `metrics/netlify.toml`.
GET/HEAD only (405 otherwise); same-origin (no CORS header); `Cache-Control: no-store`; reads
nothing from the request; writes nothing; no cookies; no `console.*` (Netlify's platform request
log is the only record). It serves `publish(synthetic_feed.json)`. The path to real counters
(`readRealCounters` over the `usage-counters` Blobs store) is behind
`REAL_COUNTERS_ENABLED = false` — a literal, not an environment variable — **enable only after
the L8 D1–D3 owner decisions**, and it additionally refuses until `REAL_CALENDAR` is wired.
Pinned by `metrics/tests/cohort-handler.test.mjs`.
