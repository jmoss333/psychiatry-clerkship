1 · Audit

Five sources of cognitive load

The code already knows what matters — Today ranks exactly one primary action, governance drift renders as pending everywhere, the safety kit is one panel. The layout around that logic is what overloads learners.

1

Navigation lives in four places and changes shape by device

On a phone the header wraps to two rows of six controls; below the page sits a five-slot dock whose centre slot becomes whatever Today's primary action is ("Continue", "Start review", "Resume question bank", "Open →") or, by default, "Essential". The dock's Library item is a menu that repeats the Library page's own Essentials/Everything switch plus Search, and a floating "＋ Ask a question" button overlaps content. Care is a tab on desktop and a header button on phone.

Source: fd_shell.js on main (fdHeader, fdDockModel, fdDockBrowseItem); 390×844 baselines.

Fix: four fixed destinations — Today, Path, Library, Care — in the same order on every device; Search, Ask, Safety and Settings in one bar.

2

Today stacks ten modules around the one thing it wants you to do

Active-testing banner, a seven-day activity strip, quick-tool pills, Continue, an "Also today" stack (block planner, preparation chooser, due reviews, resume, capture), an exam nudge, the week list, a daily pick, a learning-activity card and the safety rail. On the 26 September phone capture the resident's primary card starts about 650px down an 844px screen, below the banner, strip, a Care row and five tool pills. The activity strip ("Active 1 of the last 7 days") is a streak in all but name.

Source: fd_today.js + spa_index.html "Also today" assembly on main; audit/shots/res-today-390x844-due.png.

Fix: the existing One-Thing-First winner renders first as a "Now" card; everything else becomes one quiet list; the banner shrinks to one line at the top; the strip moves to the learning record.

3

Two catalogues, three vocabularies

Essentials ("Core readings", ten index filters, serif summaries, a separate tools shelf) and Everything ("Everything, one screen", 83 dot-links in five columns) file the same pages under different headings, and both differ from the week themes and the case links. "Press / to filter" opens global search rather than filtering the page. #950 unified the destination; the two views still behave like two products.

Source: fd_library.js on main; essentials-ms3-kit/full baselines.

Fix: one page, one row component, one in-page filter and one section index for both views — and every row says where it is used.

4

Everything carries the same weight

Uppercase micro-labels head almost every block. Two greens mean different things — done (#357160) and action (#3a7d6e). Terracotta, the brand and until recently the primary fill, sits next to safety red (#951 now moves tools off it). A reading opens with five pieces of chrome before its first sentence: the attested chip, a "Reviewed by" pill saying the same thing, a WARD banner, a practice box and an eleven-item table of contents.

Source: frontdoor.css + clinical-warm.css on main; front-door-reader-desktop baseline.

Fix: sentence-case labels, three status hues only, one status line per page, one raised surface per screen.

5

Workflows stop at the edge of each tool

Case Journeys already follows one fictional patient from interview to differential, treatment conversation, family meeting, safety and handoff — with links out to the matching pages. Nothing in Today, Path or the Library points back into it, and each surface phrases "what next" differently. Four resume mechanisms (Continue, the question-bank capsule, last read, a live block) arrive as four card styles.

Source: one-patient-six-weeks.html + longitudinal_case.json; fd_due.js, fd_block.js; curriculum remediation plan (24 Sept) proposing the case on all six weeks.

Fix: "Next in this thread" on every page, this week's case step on Today, and a timeline inside the case.

Keep — already working

The One-Thing-First priority order (resume › block › read › due › week › ahead › setup) · drift rendering as pending on every surface · the always-visible Safety button and single-panel kit · the week's title as Today's heading · content-height tool frames · the expanded "What am I preparing for?" chooser and its session-only choice · the readings-first Essentials · transient Library selection.

3 · Direction

One thread

Keep the information architecture learners already know, remove the duplicates, and add connective tissue made only from existing content. A single visual motif — a thin line of week and step marks — shows position in the rotation on Today, the route on Path, and the patient's course inside Case Journeys.

  1. 1

    One primary action

    Filled teal, first in reading order, on every screen. Everything else is a row or a link.

  2. 2

    Four destinations

    Today · Path · Library · Care, same order everywhere. Reading and tools are a focused mode that keeps your origin tab.

  3. 3

    Three status colours

    Teal action and progress · olive review · red safety only.

  4. 4

    Every page ends somewhere

    "Next in this thread": the case week, the tool that practises it, the conversation it prepares.

  5. 5

    Quiet, never silent

    Secondary detail folds away. Safety, unfinished work and review status never do.

Tradeoffs we accept

  • The phone dock no longer mirrors the primary action, so on a long page it is a scroll up rather than always in reach. The Now card is first, and every reading ends with its own "Mark done" and next step.
  • The activity strip leaves Today. Learners who liked it find it in Learning activity & review.
  • The week control leaves the global header; changing week takes one more tap from the Library.
  • Everything trades "one screen" scanning for a filter and section index; rows stay compact there.
  • Case Journeys' redesign edits attested tool HTML, so it waits for re-attestation (Phase 3).

Directions considered

  • Polish in place — tokens and spacing only. Cheapest, but leaves the duplicated navigation and the ten-module Today. Cosmetic.
  • Single feed — merge Today and Library into one personalised stream. Fewer tabs, but it mixes doing with finding and makes the catalogue unpredictable.
  • One thread (chosen) — same IA and data, duplicates removed, connections drawn from content that already exists.

4 · Concept

Today — what should I do now?

MS3, week 2, Thursday. The learner left a 10-minute block half done, has two reviews due and two saved questions. Review states shown are fixtures, never the live ledger. Dashed blue line = first screen (1280×800 / 390×844).

  1. Place. Week and day, the week's title, and a six-week thread that replaces the header week pill. Each mark opens that week on Path.
  2. Now card. Whatever the existing picker chooses — here the unfinished block, because block outranks due reviews. One teal button.
  3. Also today. Due reviews (olive), the week, saved questions — rows, not cards.
  4. Preparation chooser kept open with its existing copy and session-only choice; Prepare for tomorrow joins it here.
  5. This week. One row style; "Pending review" shown verbatim where it applies.
  6. On the unit this week. The matching Case Journeys step and its "Carry it to rounds" line — the bridge from reading to the patient.
  7. Rail. Safety kit first, then quick tools and the learning record. On phones Safety stays in the top bar. The active-testing notice is one line at the top (D1).

5 · Concept

Library — where can I find this?

One page, two views. Summaries, hints and counts come from today's MS3 build; the pending badge and the review banner are fixtures to show the honest state.

  1. One switch from #950, now a segmented control with counts.
  2. One filter for the current view; "/" focuses it and the existing status line announces "N of M".
  3. One section index for both views — sidebar on desktop, chips on phone.
  4. One row: title, the existing summary, then "Reading · 5 min · Week 1 · Case week 1".
  5. Preview (desktop): where it is used, what to practise with (pairings.json), status, one "Open". Transient — not saved, not in the URL.
  6. Review banner verbatim from today's Essentials.

6 · Concept · representative learning tool

Case Journeys — how does this connect to patient care?

One Patient, Six Weeks, week 2. Every prompt, example, story beat, handoff and link is copied from longitudinal_case.json. The exercise changes order, not content: try first, then reveal "One way to say it", then mark it practised — the same three checklist items, stored exactly as today.

  1. Case timeline. Six weeks with done, current and not-started marks; week 5 flagged as safety work. Same marks as Today's thread.
  2. Try → Compare → Mark practised. The example is revealed only after the learner commits. Nothing typed, nothing recorded; storage stays cw_longitudinal_v1 checks c0–c2.
  3. Next week stays locked by the existing rule and copy.
  4. Practice this part of the story — the case's own links, opening in place; Back returns to the week.
  5. Compare two weeks — two weeks of the story side by side. No new text.
  6. Crisis block stays build-injected and is never folded away.

6b · The rest of the journey

Path, reading and search use the same parts

The resident site's Path (four weeks, previewing week 4, items and prompts copied from the current build); a student reading in focused mode; global search on a phone. Week counts are fixtures.

  • The same week marks as Today's thread, larger: done, this week (partly filled), previewing (selected).
  • "Demonstrate this week" and "Ask your supervisor" stay together as the week's clinical frame.
  • One primary action — "Set as my week" — only when previewing another week.
  • Reader: one status line ("✓ faculty-attested" and the existing receipt, strings unchanged); the practice panel folds to one row; sections fold as they do today except on crisis pages; the reading ends with "Mark done", the next item in the week, and "Next in this thread". Body text, headings and order are the page's own.
  • Search: safety protocols first with the kit's own one-line cues, then pages, then tools; Close and Esc return focus to the opener.

11 · Rollout

Three small phases, one journey

Each phase ships alone, reverts with one commit, migrates no stored data and passes bin/verify.sh plus both site gates. Phases 1–2 touch no content source.

Phase 1 · shell and Today

What should I do now?

App bar and four-destination nav on both sizes; remove the dock centre slot, dock Library menu, phone Care button, floating Ask and header week pill; Today order (place + thread, Now card, Also today, chooser, this week, on the unit, rail); token additions; one focus style. After #949 and #951.

  • Exactly one filled teal button on Today for each primary kind — resume, block, read, due, week, ahead, setup — first after the heading and inside the first screen at 390×844 and 1280×800, using controlled fixtures.
  • FD_TODAY_PRIMARY_ORDER and its picker-table test unchanged; an interrupted block or capsule still leads after reload; due reviews still outrank Continue.
  • Preparation chooser keeps its open state, copy and session-only choice, and never changes the primary.
  • Same four destinations, labels and order at 320, 390, 768 and 1280px; Safety visible at all; Search one activation from every screen.
  • 1–4, "/", ⌘K and Esc work; focus returns to the invoker; aria-current on the active destination; landmarks banner, nav, main, complementary.
  • axe: no serious or critical issues; text ≥ 4.5:1, controls and focus ring ≥ 3:1 in both themes.
  • 200% text and 320px width: no horizontal scroll, nothing clipped; reduced motion: no animation.
  • Back, Forward and reload keep destination, Library view and reading place; every ?tab, ?page and ?tool link resolves.
  • check_governance_separation clean; zero new attestation drift; CLASS-INVENTORY updated in the same PR; baselines regenerated by the workflow.

Phase 2 · Library

Where can I find this?

Segmented Essentials · Everything; in-page filter; one section index and one row for both views; transient desktop preview; "Used in" and "Practice with" from existing data; empty states; search results with safety first.

  • Every shipped page appears in Everything once (essentials-inventory helper); counts match shipped_pages.json per site; Essentials stays a view of the Library.
  • Filter updates as you type on 83 items, announces "N of M" through the existing status line, and hands zero results to Search.
  • Section, filter and preview are not persisted and not in the URL unless D3 is approved.
  • Pending and high-risk badges on every row they apply to, verbatim; summaries byte-identical to topic_meta.
  • Open an item, press Back: same view, section and scroll.
  • Phase 1 accessibility, zoom, motion and history criteria hold.

Phase 3 · focused learning · needs re-attestation

How does this connect to patient care?

Reader status line and "Next in this thread" (shell); Case Journeys timeline, Try → Compare and compare-weeks (tool HTML); optional "Bring to supervision" bridge into Ask, same-origin and allow-listed.

  • Existing cw_longitudinal_v1 progress renders identically with no migration; ?week=N works.
  • Prompts, examples, reflection, handoff and links render verbatim from longitudinal_case.json; any new microcopy is listed in the PR for faculty review.
  • No learner free text, recording or new storage; reveal is a button with aria-expanded; the next-week lock is unchanged.
  • Crisis-block marker present; nothing collapses it.
  • The ledger row is registered pending in the same PR and shown honestly until the console re-attests; tests use governance fixtures.
  • From a linked page, Back restores the week and scroll.
