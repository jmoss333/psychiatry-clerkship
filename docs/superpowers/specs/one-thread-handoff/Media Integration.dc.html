Other places the same map can surface

  • Library preview: a "Go deeper" line under "Practice with", e.g. "1 episode · 1 family book".
  • Case Journeys: week 4 (family and systems) gets the family book for that case; week 1 gets an interview/alliance episode from Foundations.
  • Preparation chooser: picking "Family conversation" adds the matching book and its "How to offer it" line.
  • Search: episode and book titles become a fourth result group, "Listen & read", always below safety, pages and tools.
  • Path: one optional "Listen this week" line per week, using pairings.json's existing listen role.

How it would work

  • Data: a new curator-owned media_map.json, e.g. "t_mood.md": {"podcast":"Mood & bipolar; suicide","book":"Mood, bipolar & depression","picks":["ep25","ep201","An Unquiet Mind"]}. Episodes and books are parsed at build time from the two existing library files, so titles and links stay single-source.
  • Validation: the build fails if a pick no longer exists, the same way pairings.json is validated.
  • Governance: book_library.md and podcast_library.md are not edited. External links create verification debt; pairings.json avoids them for that reason. Start with episodes already marked "▶ YouTube" (verified) and skip "search channel" items.
  • Re-attestation: none for the shell or a new map. Whether the picks themselves need a faculty review step is your call.
  • Not counted: no "listened" tracking, minutes or badges.
