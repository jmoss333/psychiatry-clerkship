# Automation & Hooks Brainstorm — Psychiatry Clerkship Library

**Date:** 2026-09-02 · **Author:** Claude (repo survey, verified against `origin` Actions history) · **For:** Joshua Moss, MD
**Status:** proposal — nothing here is installed. Each item names the layer it lives in, what it
replaces, and which existing contract it would trip.

Scope: what to automate *next*, given what already exists. This repo is already unusually
well-instrumented (a 40-step `bin/verify.sh` mirrored to CI, ten scheduled steward/surveillance
workflows, a pre-push gate, an evidence-span gate, two tracked skills). The brainstorm therefore
targets four things: **(1)** failures that are currently silent, **(2)** rules in `CLAUDE.md` that
are enforced only at build time or not at all, **(3)** recurring hand-done chores visible in the
git log, and **(4)** the empty `.claude/settings.json` and `.claude/agents/` — there are **zero Claude Code
hooks and zero custom agents** today (two skills exist).

> **Skeleton** (`.claude/settings.json`) — hooks read the tool call as JSON on stdin; exit 2 blocks and
> sends stderr to the agent; JSON on stdout can return `permissionDecision` or `additionalContext`.
>
> ```json
> {
>   "hooks": {
>     "SessionStart": [{ "matcher": "startup|resume",
>       "hooks": [{ "type": "command", "command": "bash .claude/hooks/session-vitals.sh" }] }],
>     "PreToolUse": [{ "matcher": "Edit|Write|MultiEdit",
>       "hooks": [{ "type": "command", "command": "python3 .claude/hooks/pre-edit-guard.py" }] },
>       { "matcher": "Bash",
>       "hooks": [{ "type": "command", "command": "bash .claude/hooks/lfs-guard.sh" }] }],
>     "PostToolUse": [{ "matcher": "Edit|Write|MultiEdit",
>       "hooks": [{ "type": "command", "command": "python3 .claude/hooks/post-edit-validate.py" }] }],
>     "Stop": [{ "hooks": [{ "type": "command", "command": "bash .claude/hooks/stop-quick-gate.sh" }] }]
>   }
> }
> ```
>
> One guard script per event keeps the matcher list short; the script dispatches on `file_path`.
> `pre-edit-guard.py` sketch:
>
> ```python
> import json, re, sys
> ev = json.load(sys.stdin); ti = ev.get("tool_input", {})
> path = ti.get("file_path", ""); text = ti.get("new_string") or ti.get("content") or ""
> CRISIS = re.compile(r"\b(988|1-800-273-8255|741741|1-800-799-4889)\b")
> if CRISIS.search(text) and not path.endswith("crisis_resources.json"):
>     print("Crisis contacts live only in crisis_resources.json; use the <!-- crisis-block --> marker.", file=sys.stderr); sys.exit(2)
> if re.search(r"(^|/)(rp-[^/]*|[^/]*-trainer[^/]*)\.html$", path) and re.search(r"\b\d+(\.\d+)?\s?(mg|mcg|µg|mL|units?)\b", text):
>     print("Dose literals are banned in rp-*/-trainer tools (QA gate).", file=sys.stderr); sys.exit(2)
> if re.search(r"localStorage\.(get|set|remove)Item\(\s*['\"](?!cw_|rp_)", text):
>     print("localStorage keys must be cw_* or rp_*.", file=sys.stderr); sys.exit(2)
> PHI = [r"\b\d{6,}\b", r"\b\d{1,2}[/-]\d{1,2}[/-]\d{2,4}\b", r"\bmrn\b", r"\bmy patient\b", r"\bdate of birth\b", r"\bdob\b"]
> if re.search(r"(^|/)(0\d|1[0-4])_[^/]+/", path) and any(re.search(p, text, re.I) for p in PHI):
>     print("Looks like PHI (matches site_build/phi_heuristic.js). Content must be synthetic.", file=sys.stderr); sys.exit(2)
> INSTR = r"\b(C-SSRS|PHQ-9|GAD-7|CIWA|COWS|BFCRS|Stanley-Brown|MoCA|MMSE|AIMS)\b"
> if re.search(INSTR, text) and re.search(r"(^|\n)\s*(\d+[.)]|[0-4]\s*=)", text):
>     print(json.dumps({"hookSpecificOutput": {"hookEventName": "PreToolUse", "permissionDecision": "ask",
>       "permissionDecisionReason": "Possible instrument item/anchor text. CLAUDE.md: the library teaches administration; it does not reproduce instruments. Stop and ask."}})); sys.exit(0)
> ```

### G. Custom agents — `.claude/agents/*.md` (the specialist layer)

Hooks enforce; automations schedule; **agents do the judgment work that scripts cannot**, with a
tool allowlist as the enforcement mechanism. An agent definition is one Markdown file with YAML
frontmatter (`name`, `description`, `tools`, `model`) and a system prompt body. The same file is
picked up by Claude Code, Cowork, and the `Agent` tool from any session, so a specialist is written
once and reused by hooks (A13, A14), Routines (E1–E6), and humans (`/agents`). The `description`
is what makes the main session delegate automatically, so it must say *when* to use the agent.

Posture rule for the whole layer: **read-only agents get no `Edit`/`Write`; writing agents are
scoped by path in the prompt and never attest, merge, or narrow an instrument waiver.**

> **Example definition** — the highest-value one, showing the shape. Save as
> `.claude/agents/evidence-verifier.md`.
>
> ```markdown
> ---
> name: evidence-verifier
> description: Use when a sentence asserts what a paper found, when adding or editing an entry in evidence_annotations.json, or when validate_evidence_annotations.py fails C5. Reads the paper's results section via PubMed and stores a verbatim sourceSpan; rewrites the claim when the span does not license it.
> tools: Read, Grep, Glob, Edit, Bash, mcp__PubMed__get_full_text_article, mcp__PubMed__get_article_metadata, mcp__PubMed__search_articles
> model: opus
> ---
> You verify one claim against one source, and you write to exactly one file: evidence_annotations.json.
>
> Procedure
> 1. Locate the claim sentence on the page and its source id in evidence_registry.json.
> 2. Fetch the paper. Read the RESULTS section (and tables). Never write a span from the title, the abstract's conclusion sentence, or a commentary.
> 3. Extract the shortest verbatim passage that states the finding, with its number and its qualifier. Keep the caveat if the sentence has one.
> 4. Classify direction: positive / null / negative / mixed / descriptive.
> 5. If the page's claim is voiced more strongly than the span (a superlative, a dropped caveat, a time-course the paper does not report), do NOT store the span against that claim. Report the exact rewrite the span licenses. The claim changes; the span never does.
> 6. Run python3 13_Faculty_Resources/_automation/validate_evidence_annotations.py and report its output verbatim.
>
> Never: edit a content page, trim a span to make a claim pass, invent a numeral, or mark anything attested.
> ```

## 3. Guardrails that apply to every item

- **Report-only by default.** Anything that edits clinical teaching content is a draft PR for
  faculty, never a merge. Same posture as the surveillance ADR and the maintenance README.
- **No PHI, ever, in hook output.** Hooks print rule text and file paths, never the matched span
  (A7 in particular must not echo the text it blocked).
- **The three contracts are the cost of touching `ci.yml`.** Prefer a *new* workflow file (pinned
  once in `validate_scheduled_workflows.py`) over a new `ci.yml` step, unless the check belongs in the
  PR gate.
- **Hooks must be stdlib-only and fast (< 1 s).** They run on every edit in the web sandbox, where
  `git-lfs` and `gh` may be absent; every script must degrade to "allow" on tooling absence except
  A8, whose whole point is the absence.
- **Instrument scope is governance, not automation.** A6 asks; it never decides. Nothing here
  narrows or lifts the COWS interim waiver.
- **Agents are scoped by tool allowlist, not by promise.** A read-only agent has no `Edit`/`Write` in
  its frontmatter; a writing agent names its files in the prompt and is tested with an eval, the way
  `topic-meta-author` already is. No agent attests, merges, or decides instrument scope.
- **Bots need the write permission that is currently missing.** C1, C4, C6, C10 all depend on the
  same Actions setting that is breaking the surveillance PRs today. Fix once, unblock all.

## 4. Next best step, and the idea worth stealing

**Next best step:** ship Wave 1 item 2 (the hook bundle) first. It has no external dependency, trips
no contract, and is immediately visible in the next Cowork session — and while it is being written,
flip the Actions "allow GitHub Actions to create and approve pull requests" setting so that C1 and
the surveillance PRs start working without any code change.

**Innovative next idea — a retraction-aware evidence gate (E2 → gate).** The library already holds
the strongest evidence contract in this space: every claim carries the paper's own words. The
missing half is *time*: a span that was true in 2024 is silently wrong the day the paper is
retracted. Wire the PubMed publication-type check into `validate_evidence_annotations.py` itself
(cached, offline-safe, refreshed by E2 weekly) so a retracted source fails the **build**, not just a
surveillance report — and feed each hit into the unregistered "How We Know" page as a live
correction. The library would then teach critical appraisal using the one thing no textbook can:
its own corrections, arriving as they happen.
