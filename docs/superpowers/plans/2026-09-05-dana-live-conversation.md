# Dana live conversation prototype

The September 5 screenshot showed an architectural limitation: phrase matching treated an answer to Dana's own question, an offer to help, and permission to take time as unknown questions. The user explicitly chose live case-grounded replies with the approved Marin voice, accepting API use and a response delay.

Implemented scope: local opt-in `danaConversation=1&danaLive=1`; 4.5-second default pause; 6-second optional thinking time; Space for finalized Done speaking and Escape for interruption; existing Hold and headphone interruption controls. Ten-turn limit remains.

The browser sends original learner words and a turn ID to a loopback server. The server owns the session and computes canonical disclosure state, builds context containing only permitted case material and played conversation history, requests a short patient response, validates its output shape, and supplies Marin audio. Exact matches reuse the 75 verified recordings; novel replies are synthesized. Generated output is experimental and is not an individually reviewed case script.

The server holds encounters/audio in memory only, bounds time/size/concurrency/attempts, deduplicates turns before provider work, and cancels both stages on abort or End. A Python SDK worker uses the previously authorized credential solely through its environment. Browser assets cannot expose environment files or server source. Hosted configuration, canonical case content, review status, and managed-voice eligibility are unchanged.

Verification covers canonical gate parity and missing locked facts, interrupted-context handling, HTTP host/origin/path checks, forged state/history rejection, deduplication/cancellation/limits, SDK pins and error redaction, recording integrity reuse, browser startup/turn playback/cleanup, and the user's actual screenshot phrases through a bounded live API audition. Automated checks do not establish acoustic recognition quality or eliminate model hallucinations.

Next trial: repeat the user's natural opening, a longer reflection, an interruption containing a negation, a topic follow-up, and an unknown-detail question using a real microphone and headphones. Evaluate conversational coherence and fidelity separately from voice quality; do not grade pauses or fluency. A subsequent innovation can stream speech earlier to reduce the current generation wait.

Final local verification: 244 SP tests, 33 dedicated browser scenarios, and 1,768 root static tests passed. Preview generation is reproducible. A ten-turn real API audition produced all replies and Marin audio in 3.17–4.88 seconds per submitted turn; it did not test acoustic recognition. The canonical response menus were replaced by source-bound fact summaries, and playback claims now identify the exact reply whose audio completed. Unknown-detail and transcription-noise follow-ups were checked separately; harmless garbling can still elicit a brief clarification. This remains a local prototype, with no learner release or faculty sign-off.

The later latency refinement removes complete-MP3 buffering on both sides. Text remains validated before speech begins; one bounded producer streams to native browser audio, with completion receipts and cancellation by audio token or known turn ID. A three-turn same-audio Chromium comparison measured 0.792–0.995 seconds earlier audible playback (15–21%), while retaining the existing models, case context, voice instructions, and pause controls.

Streaming verification: 261 SP tests and all 36 browser scenarios passed, including complete and truncated native MP3 streaming with no skips. The live server on port 4319 was refreshed after these checks.

The later missing-reply report exposed a reproducible shortcut ambiguity: a second Space while waiting cancelled Dana without a durable transcript explanation. Space now only finishes the learner turn; Escape interrupts. Pending, cancelled, and failed responses remain annotated beside unanswered questions, including after Resume and late callbacks. The user's exact historical cause is unconfirmed. Verification after this fix: 269 SP tests and 38 browser scenarios passed; source freshness was confirmed on port 4319 without restarting the user's active encounter.

The approved first-sentence experiment is a separate Python SDK benchmark and saved listening comparison. Three runs received lead audio 0.546–0.750 seconds earlier than whole-reply synthesis, with the remainder ready before the estimated lead end. These measure audio arrival, not first audible words. All nine MP3s decoded; exact prefix/final response and failure contracts passed. The live player remains continuous until sentence joins and segmented cancellation/partial-delivery semantics are evaluated. See `DANA_CONVERSATION.md` for the local audition URL and evidence limits.

The user subsequently requested the refinement. Implemented: stream actor text to private lead synthesis, withhold all audio URLs until complete-response format/identity/prefix validation and clean worker exit, then publish one or two exact ordered segments. Preload both; play the remainder without waiting for the first receipt; acknowledge heard only after every segment ends and every matching receipt succeeds. One shared cancellation scope and 4 MB turn cap cover actor and speech jobs, with separate process ceilings of 60 actor and 60 speech attempts. A failed speculative lead cancels composition; a failed remainder cannot enter heard history.

Final verification: 302 SP checks and 45 dedicated browser scenarios passed. Two reproduced whitespace lookup failures were fixed by preserving exact patient-text interiors; learner normalization is unchanged. Three real API/native Chromium turns completed all six segments at normal speed, first playback 2.837–6.092 seconds after submission and after validated metadata in every case. This is integration evidence, not a controlled speed comparison or acoustic naturalness assessment. Port 4319 was refreshed after these checks; the refinement remains local and disabled for learners.
