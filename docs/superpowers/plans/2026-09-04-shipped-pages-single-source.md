Existing readers migrate in phases; a ratchet test stops new direct readers.

## 1. The artifact

`13_Faculty_Resources/_automation/site_build/shipped_pages.json` (tracked; 2-space indent; keys sorted; pages sorted by `slug`):

```json
{
  "version": 1,
  "_note": "GENERATED by site_build/shipped_pages.py — do not hand-edit. Regenerate: python3 13_Faculty_Resources/_automation/site_build/shipped_pages.py --write",
  "generated_from": {
    "site_manifest.json": "<sha256>",
    "cotw_registry.json": "<sha256>",
    "resident_section.py": "<sha256>",
    "surface_governance.py": "<sha256>"
  },
  "pages": [
    { "slug": "cotw_20260831_catatonia_ms3.md", "kind": "page", "sites": ["ms3"], "title": "Catatonia (Aug 31) — MS3", "source": "08_Cases_and_Simulation/case-of-the-week/2026-08-31_..._MS3.md", "producer": "cotw_registry" },
    { "slug": "mse.html", "kind": "tool", "sites": ["ms3", "res"], "title": "Mental Status Exam", "source": "...", "producer": "site_manifest" }
  ]
}
```

- `producer ∈ {site_manifest, cotw_registry, resident_extra, resident_tool}`. `sites` is a sorted subset of `["ms3","res"]`.
- `generated_from` hashes are informational (lets a reader explain staleness); the **gate** is regenerate-and-diff, not hash comparison.
- Schema: `shipped_pages.schema.json` beside it; register the pair in `validate_registry_schemas.py` (and its `PAIRS` tuple test).

## 2. Deliverables (one PR, in this order)

### D1 — `site_build/shipped_pages.py` (the derivation)
- Pure function `derive(root) -> dict`. Inputs: `site_manifest.json`, `cotw_registry.json`, and the resident-only extras. **Do not re-type the resident extras:** import them from `resident_section.py` if they are module-level constants; if they are only reachable by executing the build, refactor the minimal constant out of `resident_section.py` into a small importable module (`site_build/resident_extras.py`) that `resident_section.py` then imports — the build must keep producing byte-identical output (see D3). Same treatment for the resident-only tools list in `surface_governance.py`.
- The COTW slug MUST come from one shared Python helper. Extract `_cotw_slug` into `site_build/cotw_slug.py`; make `build_deploy.py`, `resident_section.py`, `cotw_meta.py`, and `validate_attestation_consistency.py` import it. Delete their private copies.
- Modes: `--write` (regenerate the tracked file), `--check` (regenerate in memory, diff against the tracked file; exit 1 with a unified diff and the `--write` command if stale), `--check-build <OUT> --site ms3|res` (compare the tracked file's `pages` filtered by site against the real `_build/<site>/content/*.md` + `tools/*.html` listing; exit 1 listing every slug on one side only).
- Deterministic: same inputs → byte-identical output. Test it by writing twice and comparing.

### D2 — Gates
- `build_and_check.sh`: after the build, run `shipped_pages.py --check-build "$OUT" --site "$SITE"`. **A disagreement fails the build.** This is the structural guarantee — the derivation cannot drift from reality without the build going red.
- `ci.yml`: one step `python3 …/shipped_pages.py --check`. Adding a ci.yml step trips three contracts (CLAUDE.md "Adding a step to ci.yml"): mirror it in `bin/verify.sh`; recompute the workflow digest via `validate_scheduled_workflows.py`'s own `_load`/`_contract_digest`; add the schema pair to `test_validate_registry_schemas.py`'s `PAIRS`.
- `.claude/hooks/post_edit_validate.py`: after an edit to `site_manifest.json` or `cotw_registry.json` (or the resident extras module), run `--check` and print the `--write` command on failure. Extend `tests/hooks.test.mjs` for it.
- Pre-commit (`bin/install-hooks.sh` gate) — include `--check` if the existing gate structure makes it a one-liner; otherwise rely on verify.sh.

### D3 — Build parity proof (before touching any consumer)
- Build both sites from clean `origin/main` (`build_and_check.sh ms3`, `res`) and record `find _build/<site> -type f | sort | xargs sha256sum` for each. Re-run after D1/D2. **The learner site output must be byte-identical** except for nothing — the build's page set is unchanged by design. Paste the two-line comparison in the PR body. If anything differs, stop and report; do not "fix forward".

### D4 — Migrate the attestation family (the readers this incident was about)
- `faculty-console/content-universe.mjs`: `deriveContentUniverse` now takes `{ shipped }` and returns the universe from `shipped_pages.json` (kind, title, and `site` = `'res'` if `sites` is exactly `["res"]`, else `'ms3'`). Keep a test that cross-derives from manifest+registry and asserts equality with the shipped file — that is the JS-side parity check.
- `faculty-console/netlify/functions/attest.mjs`: read `shipped_pages.json` from the attestation branch instead of manifest + registry; `manifestRevision` semantics stay (the console's conflict detection keys on it — read `app.mjs` before renaming anything). Update `tests/faculty-console-handler.test.mjs` and `-branch-sync.test.mjs` fixtures.
- `faculty-console/check_pending_visible.mjs`: universe from `shipped_pages.json`; keep `NOT_REVIEWABLE_IN_CONSOLE`.
- `validate_attestation_consistency.py`: `manifest_items` from `shipped_pages.json`; delete `cotw_built_slugs()`.
- README (`faculty-console/README.md`) and the #521 CLAUDE.md gotcha: point at `shipped_pages.json` as **the** reference; keep the incident paragraph.

### D5 — The ratchet (what makes this durable)
- `tests/shipped-pages-readers.test.mjs`: greps the repo (tracked files only; exclude `docs/`, `99_Archive/`, `*.md`, tests, and `shipped_pages.py` itself) for `site_manifest.json` / `cotw_registry.json` string literals and asserts the set of files equals a frozen `ALLOWED_DIRECT_READERS` list = exactly today's readers minus the D4 migrations. Any new direct reader fails; removing one from the list is the only permitted edit (add a comment: "this list may only shrink"). Include the build scripts and hooks in the allowlist — they are producers/guards, not consumers.
- `decisions.json`: add a decision `shipped-pages-single-source` (decided 2026-09-04, decidedBy Joshua Moss, MD, `rationaleRef` = this ADR, `governs` = [`tests/shipped-pages-readers.test.mjs`, `site_build/shipped_pages.py`]) so `bin/check_decision_drift.py` ties the enforcement to a recorded decision. Validate against `decisions.schema.json`.
