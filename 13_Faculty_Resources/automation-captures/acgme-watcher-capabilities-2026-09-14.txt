--- WHAT THIS CAPTURE DOES *NOT* SHOW ---

The list above contains no entry for the remote-devices server. That is the server behind
Desktop_Commander, device_bash, device_stage_files and device_commit_files — every path from a
cloud task to this machine. Its absence means the task has, at fire time:

  NO git          NO gh           NO filesystem access to ~/Psychiatry-Clerkship-Library
  NO Desktop_Commander            NO device_bash

So this mechanism can do exactly one thing: read the Gmail thread and report. It CANNOT save a
rights capture, edit standards.json, add a decisions.json entry, run verify.sh, or open a PR.
Its prompt was rewritten on 2026-09-14 to match — it detects the reply, quotes the operative
sentences verbatim, classifies Q1/Q2 as yes / no / not-addressed, and hands the repo work back
as a checklist for a human. It deliberately does not auto-merge: a rights-posture change is a
human review gate.

A followUp block declaring requires: ["Gmail"] is proven by this capture.
A followUp block declaring requires: ["Gmail", "remote-devices"] is NOT, and must fail the gate.
That second case is the whole reason bin/research-dock.py grew INV-CAP.
