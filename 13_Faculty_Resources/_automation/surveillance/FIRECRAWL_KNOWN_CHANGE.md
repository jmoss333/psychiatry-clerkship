# Controlled Firecrawl change test

Manually dispatch `firecrawl-known-change.yml` to test a known, nonclinical edit. This workflow has no schedule and is not enrolled in production failure/recovery reporting. It does not run the faculty collector, modify the production inbox, or give review credit.

Each run creates a unique orphan branch under `automation/firecrawl-fixture/`. Its entire tree is one public `fixture.md` file: a clearly labeled fictional library-sorting instruction. Version A uses shelf Cedar; version B uses shelf Maple. The raw GitHub URL remains identical for all observations. No clinical material is published. The branch is retained as an audit fixture, with both commit IDs recorded in the artifact; it can be removed manually after evidence retention is no longer needed.

The four Firecrawl requests share a unique tracking tag and the production extraction settings (`maxAge: 0`, `storeInCache: false`, main-content markdown). The expected provider sequence is `new`, `same`, `changed`, `same`. Direct HTTP checks first require the exact expected public bytes. These checks wait at most 25 attempts with 15-second spacing per observation for CDN propagation; they consume no Firecrawl requests. A stale provider response, missing identity/version, unusable retrieval, or unaligned baseline makes the result inconclusive. There are no Firecrawl retries, and at most four requests are attempted.

The provider baseline timestamp must align within five seconds of an earlier observed fetch window whose text matches the immediately preceding version. This accommodates providers retaining a content-identical earlier observation, without accepting an unknown history. Alignment is evidence, not a cryptographic lineage guarantee.

A pass requires all four valid observations, the expected statuses, and exact and normalized text changes matching the controlled sequence. A complete mismatch is `disagreement` (exit 1); incomplete coverage is `inconclusive` (exit 2). An initial receipt and pre-request checkpoint keep interrupted runs visibly incomplete and count any attempted request. Artifacts retain only synthetic text and allowlisted provider metadata for 90 days.

The GitHub token needs `contents: write` to publish the fixture; GitHub does not restrict that token to a single branch. The script restricts writes to its newly generated fixture ref, creates no parent tree from main, uses no force update, and refuses a foreign head. Checkout credentials are not persisted. Firecrawl and GitHub credentials never enter the artifact.

A successful test demonstrates detection of this one synthetic sentence change. It does not establish sensitivity to real guideline changes, reliably distinguish layout from recommendations, or validate clinical teaching. Those remain separate evaluations with faculty governance.

## Formatting-only control

Choose `change_kind=emphasis` to bold only the word Cedar while retaining every word and the same URL. The default `wording` case remains Cedar to Maple. Both variants are limited to four requests. If the extractor removes the distinguishing emphasis or serves stale content, the version cannot be established and the result is inconclusive; a quiet response alone is not proof that the formatting change was observed.

After four usable observations, `facultyReplay` runs the production retrieval assessment, full-snapshot passage delta, question impact scanner, and packet merger entirely in memory, using a synthetic question with an explanation and distractor feedback. It records new packets per observation, retained packets, and candidate count. No production registry, mapping, inbox, or faculty decision is written. This measures packet creation, not delivery of a UI notification, and does not exercise source-specific passage maps. The synthetic question provides a known relationship so zero findings cannot be explained by missing question coverage.

`formattingOnlyAlert=true` means the harmless emphasis edit would create a review packet in that replay. A successful probe can therefore expose unnecessary faculty work; its `verdict=pass` means the observations were valid and the expected change was detected, not that noise filtering succeeded. An incomplete probe leaves this field null. Offline controls verify whitespace reflow stays quiet and a wording edit creates a packet. The inbox now classifies balanced `**plain words**` changes as `formatting-only` when all other text and mapping receipts agree and question scanning is complete. These observations update the saved baseline without creating a new faculty packet; existing packets and mapping recovery remain intact. Wording, numbers, negation, punctuation, mapping changes, and uncertain Markdown remain reviewable. Code, links, escapes, HTML, tables, and other unsupported markup deliberately fall outside this narrow allowlist. The raw comparison hash and diff are retained; this is not a general Markdown normalizer or a clinical judgment.


### Known FDA heading-identifier noise

A second, source-specific `formatting-only` rule recognizes the observed clozapine FDA page only. All ten known level-two heading links must retain their labels, order, exact same-page address and escaped-fragment spelling. Each snapshot must contain ten unique 13-character lowercase hexadecimal identifiers sharing an eight-character batch prefix; the prefix must change between snapshots. Every other character and all nonempty mapped-passage observations must remain identical, and the question scan must be complete. Code/HTML contexts, missing or duplicate headings, partial identifier changes, different sources/extractors, genuine reference-link edits and wording changes still create review packets. The rule does not dismiss existing packets or confer faculty approval.

`tests/maintenance/test_firecrawl_fda_headings.py` exercises packet creation for wording and link changes alongside the quiet generated-ID control. The original live false alert was surveillance run 38282684072: ten identifiers changed, with identical remaining text and mapped passages. Replaying saved responses requires no new collection requests.
